# 온디바이스 진단 단말 하드웨어·소프트웨어 설계 (Orange Pi 5 + SUDA)

> CropCare AI를 클라우드 없이 밭에서 쓰는 **독립형 진단 단말기**로 만드는 설계 문서입니다.
> 오렌지파이 5(16GB)에 카메라·마이크·스피커를 연결하고, 음성 대화는 **마음AI SUDA**(온디바이스 음성·대화형 파운데이션 모델)를 사용합니다.
>
> 목표 UX: **"버튼 누르거나 말 걸고 → 찍고 → 귀로 듣는다"** — 화면 없이도 진단부터 농약 안내까지 완결.
> 관련 문서: 배포 [ORANGEPI5_DEPLOY.md](ORANGEPI5_DEPLOY.md) · 양자화/NPU [QUANTIZATION.md](QUANTIZATION.md) · SUDA 방향성 [SUDA_INTEGRATION.md](SUDA_INTEGRATION.md)

---

## 1. 시스템 개요

```
                    ┌──────────────── Orange Pi 5 (16GB, RK3588S) ────────────────┐
 [사용자 음성] ──▶ 마이크 ──▶ ┌─────────────┐      ┌──────────────────────────┐  │
                    │         │ SUDA         │◀────▶│ 디바이스 에이전트          │  │
 [안내 음성]  ◀── 스피커 ◀── │ (음성 대화)   │      │ device/agent.py          │  │
                    │         └─────────────┘      │  - 대화 의도 → 동작 매핑   │  │
 [촬영 버튼] ──▶ GPIO ─────────────────────────────▶│  - 카메라 캡처(OpenCV)    │  │
 [상태 LED]  ◀── GPIO ◀────────────────────────────│  - 결과 JSON → 발화 전달  │  │
                    │                               └────────────┬─────────────┘  │
 [작물]      ──▶ 카메라 ───────────────────────────────────────▶ │ HTTP(localhost) │
                    │                               ┌────────────▼─────────────┐  │
                    │                               │ 기존 FastAPI 백엔드        │  │
                    │                               │  /diagnose /refine        │  │
                    │                               │  CNN(NPU/CPU) + SQLite   │  │
                    │                               └──────────────────────────┘  │
                    └────────────────────────── 인터넷 연결 불필요 ────────────────┘
```

**설계 원칙**

1. **백엔드 재사용** — 진단·재촬영·이력·농약 로직은 기존 FastAPI를 localhost로 호출. 웹 버전과 단말 버전이 한 코드베이스 공유
2. **SUDA는 창구, 사실의 원천은 DB** — 농약명·희석배수·PHI는 백엔드 JSON 값 그대로 발화 (환각 방지, SUDA_INTEGRATION.md 3장 원칙)
3. **음성 우선, 화면 선택** — 디스플레이는 옵션. 있으면 기존 Next.js UI를 키오스크 모드로 재활용
4. **완전 오프라인** — 추론(NPU/CPU)·음성(SUDA)·데이터(SQLite) 전부 보드 안에서 처리

### 예산 배분안 (40만 원)

| 안 | 구성 | 소계 | 남는 예산 |
|---|---|---|---|
| **A. 음성 전용 (권장 시작)** | #1~10 필수 품목 전부, 카메라·마이크를 중상급으로 | 약 22~32만 원 | **8~18만 원** → 예비비(파손·재구매)로 유지 |
| B. 디스플레이 포함 | #1~10을 하급~중급으로 조이고 + 7" 터치 | 약 35~40만 원 | 0~5만 원 (예비비 없음) |

**권장: A안으로 시작.** 이유 —
- 이 단말의 핵심 가설은 "화면 없이 음성만으로 되는가"이므로, 카메라(AF 품질)와 마이크(야외 인식률)에 예산을 싣는 게 검증 가치가 높음
- 디스플레이는 로드맵 5단계(현장화)에서 사용자 테스트 결과 "화면이 필요하다"로 나오면 남은 예비비로 추가 — 되돌릴 수 없는 선지출을 피함
- 예비비는 야외 테스트 중 파손·방수 실패 대비로도 필요

## 3. 모듈별 연결·확인 방법

### 3-1. 카메라 (USB UVC)

```bash
sudo apt install -y v4l-utils
v4l2-ctl --list-devices                 # /dev/video* 확인
# 캡처 스모크 테스트 (OpenCV)
python3 -c "import cv2; c=cv2.VideoCapture(0); ok,f=c.read(); print(ok, f.shape if ok else None)"
```

- 해상도는 1920×1080으로 캡처 후 백엔드에 그대로 업로드 (전처리·리사이즈는 서버/모델 쪽 기존 파이프라인이 담당)
- AF 동작 확인: `v4l2-ctl -d /dev/video0 --list-ctrls | grep focus`

### 3-2. 오디오 (마이크·스피커)

```bash
sudo apt install -y alsa-utils
arecord -l && aplay -l                  # 장치 인덱스 확인
arecord -D plughw:1,0 -f S16_LE -r 16000 -d 3 test.wav && aplay test.wav   # 녹음→재생 루프백
```

- SUDA가 요구하는 샘플레이트(통상 16kHz)로 마이크 캡처 설정
- `.asoundrc`로 기본 장치 고정 (USB 장치 순서 바뀜 방지: `udev` 규칙으로 심볼릭 이름 부여 권장)

### 3-3. GPIO (버튼·LED)

> 납땜 없이 점퍼선·브레드보드로 연결한다. 헤더가 안 붙은 모듈만 피해서 구매하면 된다.

| 신호 | 핀(26핀 헤더 예시) | 방식 |
|---|---|---|
| 촬영 버튼 | GPIO IN + 내부 풀업 | 눌림=LOW, 디바운스 50ms |
| 상태 LED | GPIO OUT ×3 (R/G/B) | 대기=녹색 점등, 듣는중=청색, 진단중=청색 점멸, 결과=녹/적 |

- 라이브러리: `wiringOP` 또는 `gpiod`(권장, `libgpiod` python 바인딩)
- ⚠️ 오렌지파이 5 핀맵은 라즈베리파이와 다름 — 보드 매뉴얼의 핀 번호표 기준으로 배선

### 3-4. RTC (선택)

```bash
sudo apt install -y i2c-tools
i2cdetect -y 2                          # DS3231 = 0x68
# overlay 활성화 후 hwclock 동기화 (armbian-config → overlays → i2c/rtc)
```

## 4. SUDA 통합 설계

### 4-1. 역할 분담

| 계층 | 담당 | 구현 |
|---|---|---|
| 음성 인식·대화·합성 | **SUDA** | 마이크 입력 → 의도/발화 생성 → 스피커 출력 (STT-LLM-TTS 통합, 온디바이스) |
| 의도 → 동작 실행 | 디바이스 에이전트 | "찍어줘"→캡처, "얼마나 타?"→백엔드 조회 등 |
| 진단·데이터 | 기존 FastAPI | 변경 없음 |

### 4-2. 에이전트 ↔ SUDA 인터페이스 (SDK 확보 후 확정)

SUDA SDK의 제공 형태에 따라 두 가지 패턴 중 하나로 붙입니다:

- **패턴 A — 툴/함수 호출형** (SDK가 지원 시 권장): SUDA에 `take_photo`, `get_diagnosis`, `get_pesticide_info`, `get_history` 같은 도구를 등록 → SUDA가 대화 중 직접 호출. 자연스러운 대화 흐름
- **패턴 B — 의도 라우팅형** (폴백): SUDA는 대화만 담당, 에이전트가 발화 텍스트에서 의도를 분류(키워드/경량 분류기)해 동작 실행 후 결과 텍스트를 SUDA에 넘겨 발화

### 4-3. 컨텍스트 주입 (환각 방지 — 안전 요건)

```
시스템 프롬프트: "너는 농작물 진단 안내원. 아래 JSON에 있는 사실만 말한다.
                 JSON에 없는 농약·용법 질문은 '농업기술센터 문의' 안내로 답한다."
+ 진단 결과 JSON (병명, 확률, 설명, 등록농약: 희석배수·PHI·사용횟수)
```

- 숫자(희석배수·PHI·횟수)는 SUDA가 생성하지 않고 **JSON 값을 문장에 삽입만** 하도록 프롬프트·후처리 이중 방어
- 발화 내용은 로그로 남겨 검수 가능하게 (안전 이슈 추적)

### 4-4. 대화 시나리오 (1차 구현 범위)

| 시나리오 | 흐름 |
|---|---|
| 진단 | "이파리 좀 봐줘" → 촬영 안내 → 캡처 → `/diagnose` → 결과 낭독 |
| **재촬영 유도** | refine 필요 응답 시 → "잎을 뒤집어 뒷면을 찍어주세요" → 2차 캡처 → `/refine` → 재확정 낭독. ※ [[patent-recapture]] 발명의 하드웨어 실시예 — 특허 명세서 반영 검토 |
| 농약 문답 | "물에 얼마나 타?" / "언제 수확 가능해?" → 결과 JSON 기반 답변 (PHI 날짜 계산 포함) |
| 이력 | "지난번엔 뭐였지?" → `/history` 조회 요약 |
| 범위 밖 | 정해진 안전 문구 + 전문가 안내 |

### 4-5. ⚠️ 선결 확인 사항 (마음AI 문의 리스트)

1. **RK3588(S) 지원 여부** — 발표된 탑재 사례는 퀄컴 NPU. RK3588 NPU 미지원 시 CPU 실행 성능(A76×4)과 메모리 요구량
2. SDK 제공 형태: 네이티브 라이브러리 / Python 바인딩 / 컨테이너, 라이선스·과금 구조
3. 툴/함수 호출(패턴 A) 지원 여부, 시스템 프롬프트·컨텍스트 주입 방식
4. 한국어 농업 어휘(작물·병명·사투리) 커스텀/파인튜닝 가능 여부
5. 마이크 요구 스펙(샘플레이트·채널), 웨이크워드 지원 여부

> **리스크 헤지**: RK3588 미지원 판정 시에도 아키텍처는 유지됩니다. SUDA 자리에 오프라인 STT/TTS(예: sherpa-onnx) + 규칙 기반 대화를 끼우면 동일 UX의 축소판이 되고, SUDA는 퀄컴 기반 보드/모바일 타깃으로 이월합니다.

## 5. 소프트웨어 구성 (`device/` 신규 모듈)

```
device/
├── agent.py          # 메인 루프: SUDA 세션 ↔ 동작 실행 오케스트레이션
├── camera.py         # OpenCV 캡처, AF 트리거, 품질 체크(흔들림·노출)
├── audio.py          # ALSA 장치 관리 (SUDA SDK가 직접 다루면 축소)
├── gpio.py           # 버튼 인터럽트, LED 상태 표시
├── backend_client.py # localhost FastAPI 호출 (httpx): diagnose/refine/history
├── suda_adapter.py   # SUDA SDK 래퍼 — 패턴 A/B 분기 지점
└── config.py         # 장치 경로, 핀맵, 프롬프트 템플릿
```

- 실행: systemd 서비스 `cropcare-device.service` (backend 기동 후 시작, `After=cropcare-backend.service`)
- 백엔드 추론은 [QUANTIZATION.md](QUANTIZATION.md)의 RKNN 경로(`ML_RUNTIME=rknn`) 적용 — NPU 3코어 중 CNN이 일부만 써도 수십 ms라 SUDA와 자원 경합 여지 낮음 (실측 필요)

### 상태 머신

```
IDLE(녹색) ─버튼/웨이크─▶ LISTENING(청색) ─의도:진단─▶ CAPTURE ─▶ DIAGNOSING(청색점멸)
   ▲                                                                    │
   └────────── SPEAKING(결과 낭독, 후속 질문 대기 10s) ◀─────────────────┘
                          │ refine 필요
                          └─▶ RECAPTURE_GUIDE(음성 유도) ─▶ CAPTURE(2차) ─▶ …
```

## 6. 개발 로드맵

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| **0. 준비** | 부품 조달, ORANGEPI5_DEPLOY.md대로 풀스택 기동, 마음AI에 4-5 문의 발송 | `/health` OK + 모듈별 스모크(3장) 통과 |
| **1. 유선 흐름** | 버튼 → 캡처 → `/diagnose` → 결과를 임시 TTS로 낭독 | 실제 잎 촬영→음성 결과까지 무인터넷 시연 |
| **2. 재촬영 유도** | refine 흐름 음성 안내 연결 | 혼동쌍 샘플에서 2차 촬영 재확정 동작 |
| **3. SUDA 탑재** | suda_adapter 구현, 대화 시나리오 4종(4-4) | 자연어로 진단·농약 문답 왕복 |
| **4. NPU 전환·최적화** | RKNN 추론 + 발열·전력 실측 | 연속 50회 진단 시 스로틀링 없음 |
| **5. 현장화** | 케이스·배터리·AP모드, 밭 실사용 테스트 | 고령 사용자 3인 이상 무보조 사용 성공 |

**1~2단계는 SUDA 없이 진행 가능**하므로 마음AI 회신을 기다리는 동안 병행합니다.
