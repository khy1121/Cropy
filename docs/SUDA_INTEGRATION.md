# 마음AI SUDA 활용 방향성 및 아이디어

> **SUDA**(Seamless Uninterrupted Dialogue Agent)는 마음AI의 온디바이스 음성·대화형 파운데이션 모델입니다.
> 기존 STT → LLM → TTS 3단계 파이프라인을 하나의 오디오 파운데이션 모델로 통합해, **인터넷 연결 없이** 기기 위에서
> 약 1.5초 이내 응답의 자연스러운 실시간 음성 대화를 처리합니다 (퀄컴 저전력 칩 NPU 탑재 사례 보유).
>
> 이 문서는 SUDA를 CropCare AI에 어디에, 왜, 어떻게 적용할지에 대한 방향성을 정리합니다.

---

## 1. 왜 CropCare AI에 SUDA인가 — 문제 적합성

CropCare AI의 사용자와 사용 환경은 SUDA의 강점과 정확히 맞물립니다.

| 현장의 문제 | SUDA가 해결하는 방식 |
|---|---|
| **밭·비닐하우스는 통신 음영지역이 많다** — LTE가 끊기는 산간 농지, 철골 하우스 내부 | 온디바이스 처리라 **오프라인에서 완전 동작** |
| **주 사용자는 고령 농업인** — 작은 글씨, 복잡한 터치 UI가 진입장벽 | **말로 묻고 귀로 듣는** 인터페이스. 텍스트 크기 토글(TextSizeToggle)보다 근본적인 접근성 |
| **작업 중 손이 자유롭지 않다** — 흙·농약 묻은 장갑, 한 손엔 작물 | **핸즈프리** 조작: "사진 찍어줘", "결과 읽어줘" |
| **농약 안전정보는 읽기 어렵고 실수하면 위험** — 희석배수, 수확 전 사용금지일(PHI) | 음성으로 또박또박 읽어주고, 되물으면 다시 설명하는 **대화형 안내** |
| **클라우드 LLM은 비용·지연·개인정보 부담** | 온디바이스라 API 비용 0원, 농지 위치·재배 정보가 기기 밖으로 나가지 않음 |

핵심 통찰: **CropCare의 진단(CNN)은 이미 온디바이스화가 가능한 CPU 추론이고, SUDA도 온디바이스다.
→ "인터넷 없는 밭 한가운데서 진단부터 방제 안내까지 끝나는 완전 오프라인 농사 도우미"라는 차별화된 포지션이 가능하다.**

## 2. 적용 아이디어 (우선순위순)

### 🥇 A. 음성 진단 도우미 — "찍고, 묻고, 듣는다"

진단 전 과정을 음성 대화로 감싸는 핵심 시나리오.

```
농부: "고추 잎에 까만 점이 생겼어"
SUDA: "잎 앞면이 잘 보이게 사진을 찍어주세요. 촬영 버튼을 눌러드릴까요?"
      → (촬영) → CropCare CNN 진단 →
SUDA: "탄저병일 확률이 87%입니다. 병든 열매는 바로 제거하시고,
       등록 농약으로는 ○○ 수화제가 있습니다. 자세히 알려드릴까요?"
농부: "그 약 물에 얼마나 타?"
SUDA: "2,000배 희석입니다. 물 20리터에 약 10밀리리터예요."
```

- SUDA 역할: 의도 파악(진단 요청/질문 구분), 결과의 **쉬운 말 변환**("병반 면적" → "병든 부분"), 후속 질문 응대
- CropCare 역할: 이미지 진단(기존 CNN), 병해·농약 데이터 제공(기존 DB)
- **구현 포인트**: 진단 결과 JSON을 SUDA의 컨텍스트로 주입 → SUDA는 "데이터에 있는 것만 말하는" 안내자로 제한 (환각 방지)

### 🥈 B. 재촬영(Recapture) 음성 유도 — 특허 발명과의 시너지

혼동쌍 접전 시 판별부위 재촬영을 유도하는 기존 발명(`recapture.py`)은 **"어디를 어떻게 다시 찍어야 하는지"를 전달하는 것이 핵심**인데, 화면 안내보다 음성 안내가 압도적으로 효과적입니다.

```
SUDA: "두 가지 병이 비슷하게 나왔어요. 정확히 구분하려면
       잎을 뒤집어서 뒷면을 찍어주세요. 뒷면에 하얀 곰팡이가
       있는지가 중요합니다."
```

- 사용자가 카메라를 들고 있는 동안 화면을 볼 수 없다는 물리적 제약을 음성이 해결
- "조금 더 가까이", "빛이 부족해요" 같은 **실시간 촬영 코칭**으로 확장 가능
- 특허 명세서에 "음성 유도 수단"을 실시예로 추가할 가치 있음 (권리범위 확장)

### 🥉 C. 농약 안전 음성 브리핑 — "치지직" 없는 안전 문답

PSIS 등록농약 데이터(희석배수, PHI, 안전사용기준)를 대화로 풀어주는 기능.

- "이 약 뿌리고 언제 수확할 수 있어?" → "수확 14일 전까지만 사용 가능합니다. 오늘 뿌리면 ○월 ○일부터 수확하세요." (날짜 계산까지)
- "두 번 뿌려도 돼?" → "사용횟수 2회 이내입니다. 이력에 1회 기록이 있으니 이번이 마지막입니다." (진단 이력 DB 연동)
- 오독·오용으로 인한 **농약 사고 예방**이라는 사회적 가치 → 정부 과제·지자체 보급 사업 어필 포인트

### D. 진단 이력 음성 조회·기록

- "지난주에 뭐라고 나왔었지?" → 이력 DB 조회 후 요약 읽어주기
- "오늘 3번 밭에 약 뿌렸다고 적어줘" → 음성 방제 일지 (진단 이력에 방제 기록 추가)
- 고령 사용자가 가장 어려워하는 "찾아 들어가는" 내비게이션을 대화 한 마디로 대체

### E. Incubox(배양 검사기)와의 결합 — 하드웨어 음성 인터페이스

탄저병 잠복감염 배양 검사기(Incubox)는 화면이 작거나 없는 임베디드 기기입니다. SUDA가 퀄컴 저전력 칩 NPU에서 동작한 사례가 있으므로 **기기 자체에 음성 인터페이스를 탑재**하는 방향과 자연스럽게 이어집니다.

- "검사 얼마나 남았어?" → "3번 트레이는 18시간 후 판정됩니다"
- 판정 완료 시 음성 알림: "2번 트레이에서 탄저병 양성이 나왔습니다"
- 격자 트레이 장입 절차를 단계별 음성 가이드로 안내 (실험 프로토콜 준수율 향상)

### F. (장기) 음성 문진 보조 진단

사진만으로 애매할 때 SUDA가 문진으로 정황 정보를 수집해 진단 신뢰도를 보정:

- "언제부터 그랬나요?", "최근 비가 많이 왔나요?", "포기 전체가 그런가요, 일부인가요?"
- 수집된 답변(발병 시기·기상·분포 패턴)을 규칙 기반 가중치로 CNN 확률에 결합
- 재촬영 유도(B)의 다음 단계 발명으로 특허 연속 출원 후보

## 3. 아키텍처 방향

### 단계별 통합 전략

```
Phase 1 (웹 프로토타입)          Phase 2 (모바일 앱)              Phase 3 (완전 오프라인)
┌─────────────────┐          ┌──────────────────┐          ┌──────────────────────┐
│ Next.js 웹       │          │ 모바일 앱          │          │ 모바일 앱 / Incubox    │
│ 브라우저 마이크    │          │ ┌──────────────┐ │          │ ┌──────────────────┐ │
│   ↓ 음성          │          │ │ SUDA 온디바이스│ │          │ │ SUDA 온디바이스     │ │
│ 서버측 SUDA(데모) │          │ └──────┬───────┘ │          │ ├──────────────────┤ │
│   ↓              │          │        ↓ (온라인)  │          │ │ CNN 온디바이스      │ │
│ FastAPI 진단 API  │          │ FastAPI 진단 API   │          │ │ (모바일 변환 모델)   │ │
└─────────────────┘          └──────────────────┘          │ ├──────────────────┤ │
                                                           │ │ 병해·농약 로컬 DB    │ │
                                                           │ └──────────────────┘ │
                                                           └──────────────────────┘
```

- **Phase 1**: 현재 웹 스택에서 UX 검증. 음성 대화 흐름·프롬프트 설계를 빠르게 실험 (SUDA SDK/서버 데모 활용)
- **Phase 2**: 앱 전환 시 SUDA를 온디바이스로. 진단은 여전히 서버 API (모델 크기·정확도 우선)
- **Phase 3**: ResNet50을 모바일용으로 변환(양자화/경량화)하고 병해·농약 DB(SQLite)를 앱에 내장 → **완전 오프라인**. SQLite 기반이라 로컬 내장이 쉬운 현 구조가 그대로 자산이 됨

### 환각 방지 설계 원칙 (농약 안내는 안전 문제)

1. **SUDA는 "말하는 창구", 사실의 원천은 항상 CropCare DB** — 농약명·희석배수·PHI는 DB 값을 그대로 읽고, SUDA는 문장으로 풀기만 한다
2. 진단 확률·병해 설명도 CNN 결과와 시드 데이터 범위 안에서만 답변하도록 컨텍스트 제한
3. 범위 밖 질문("이 약 사람이 먹어도 돼?")은 정해진 안전 문구 + 전문가(농업기술센터) 안내로 회피
4. 모든 음성 안내 내용은 화면에도 동일하게 표시 (청각+시각 이중 확인)

## 4. 차별화 포인트 정리

| 관점 | 메시지 |
|---|---|
| **제품** | "통신 안 되는 밭에서도 되는" 국내 유일 완전 오프라인 병해 진단+방제 안내 |
| **접근성** | 고령 농업인 대상 음성 우선(voice-first) 농업 서비스 — 디지털 소외 해소 |
| **비용** | 클라우드 LLM API 비용 0원 → 무료/저가 보급 모델 가능, 지자체 보급 사업에 유리 |
| **특허** | 재촬영 유도 발명 + 음성 유도/음성 문진 확장 → 출원 포트폴리오 강화 |
| **하드웨어** | Incubox 임베디드 음성 UI로 소프트웨어-하드웨어 일관된 경험 |

## 5. 다음 액션 제안

1. 마음AI SUDA SDK/라이선스 제공 형태 확인 (온디바이스 배포 조건, 지원 칩셋, 한국어 농업 도메인 어휘 커스텀 가능 여부)
2. Phase 1 프로토타입: 진단 결과 JSON → 음성 브리핑 1개 시나리오(A)만 최소 구현해 고령 사용자 반응 테스트
3. 농업 도메인 발화 데이터 수집 계획 수립 (사투리·작물명·병명 발화 인식률 검증)
4. 재촬영 음성 유도(B)를 특허 명세서 실시예에 반영할지 변리사와 검토
