## 1. 한 줄 정의

**"사진 한 장, 또는 말 한마디로 병해를 진단하고 등록 농약까지 알려주는 농업인용 모바일·단말 서비스"**

- 대상 작물: 고추·무·배추 (병해 6종 + 정상 3종, 9클래스)
- 두 가지 형태
  - **A. 모바일 웹앱** — 스마트폰 카메라로 촬영 → 진단 → 농약·예방법 → 이력
  - **B. 독립 단말기** — 오렌지파이 5 + 카메라·마이크·스피커, 화면 없이 음성만으로 진단 (오프라인)

---

## 2. 문제 정의

| 현장 문제 | 근거 | 우리의 대응 |
|---|---|---|
| 농업인이 병해를 정확히 구분하지 못한다 | 무 검은무늬병 ↔ 무 노균병처럼 잎 앞면만 보면 전문가도 헷갈리는 쌍이 있음 | CNN 진단 + **판별부위(잎 뒷면) 재촬영 유도** |
| 병명을 알아도 어떤 농약을 얼마나 써야 하는지 찾기 어렵다 | 농약안전정보시스템(PSIS)은 검색이 복잡하고 모바일 친화적이지 않음 | 진단 결과에 **등록 농약·희석배수·안전사용기준(PHI)** 자동 연결 |
| 고령 농업인은 작은 글씨·복잡한 앱을 쓰기 어렵다 | 주 사용자층 60대 이상, 야외·장갑 착용 환경 | 큰 글씨 토글, 원탭 촬영, **음성 안내 단말** |
| 밭에서는 통신이 불안정하다 | 산간 농지 LTE 음영 | 단말은 **완전 오프라인**(NPU 추론 + 온디바이스 음성) |

## 3. 페르소나

### P1. 김 씨 (67세, 무·배추 노지 재배 30년)
- 스마트폰은 카카오톡·전화만 사용. 작은 글씨 못 읽음. 장갑 끼고 일함
- 잎에 반점이 보이면 농약상에 사진 보내고 답을 기다리는 게 지금 방식
- **원하는 것**: "이거 무슨 병이냐, 뭐 뿌리면 되냐"를 바로 듣는 것
- **주 사용 형태**: B 단말기 (음성)

### P2. 박 씨 (41세, 귀농 3년차, 고추 시설재배)
- 스마트폰 능숙. 블로그·유튜브로 농업 정보 검색
- 병명은 대충 알아도 등록 농약인지, PHI가 며칠인지 매번 헷갈림
- **원하는 것**: 진단 근거(신뢰도), 농약 사용법을 한 화면에서, 이력으로 재발 추적
- **주 사용 형태**: A 모바일 웹앱

### P3. 이 씨 (농업기술센터 지도사, 보조 페르소나)
- 농가 방문 시 진단 이력을 함께 보며 상담
- **원하는 것**: 이력의 사진·날짜·재촬영 여부를 근거로 상담

## 4. 핵심 시나리오

### 시나리오 S1 — 기본 진단 (모바일 웹앱, P2)

1. 박 씨가 고추 잎에 갈색 반점을 발견하고 앱을 연다
2. 홈에서 작물 칩 `🌶 고추`를 선택하고 **촬영** 버튼을 누른다 → 후면 카메라가 바로 열림
3. 잎을 화면에 꽉 차게 찍고 **진단하기**
4. 3초 내 결과: **고추 탄저병 · 신뢰도 91%**, 심각도 밴드(높음), Top-3 후보
5. 아래로 스크롤: 증상·원인·예방법 → **등록 농약 카드**(상표명, 희석배수 1,000배, 안전사용기준: 수확 7일 전까지·3회 이내)
6. 결과는 자동으로 이력에 저장. 하단 탭 **이력**에서 날짜별로 확인

**성공 조건**: 촬영부터 농약 정보까지 3탭 이내, 응답 5초 이내

### 시나리오 S2 — 혼동쌍 유도촬영 (모바일 웹앱, P2) ★ 핵심 차별점

1. 박 씨가 옆 밭 무 잎을 찍어 진단
2. 결과가 **무 검은무늬병 51% vs 무 노균병 43%** — 접전
3. 결과 위에 **재촬영 안내 패널**이 뜬다:
   > "두 병이 비슷하게 나왔어요. **잎 뒷면**을 가까이 찍어주세요.
   > 뒷면에 **회백색 곰팡이층**이 보이면 노균병, 없고 앞면 반점만 뚜렷하면 검은무늬병이에요."
4. 잎을 뒤집어 재촬영 → **재확정** 버튼
5. 1차·2차 사진을 융합해 결과 갱신: **무 노균병 70%** (뒤집힘)
6. 이력에는 "재촬영으로 재확정됨" 표시와 두 사진이 함께 남는다

**성공 조건**: 사용자가 "무엇을 봐야 하는지" 문장으로 이해하고 재촬영까지 1분 내 완료

### 시나리오 S3 — 음성 단말 진단 (독립 단말, P1)

1. 김 씨가 밭에서 단말기 **버튼을 누르거나** "이거 뭐야"라고 말한다
2. LED가 파란색(듣는 중) → 단말: *"잎을 카메라 앞에 대주세요. 찍을게요… 찰칵"*
3. LED 노란색(진단 중, 약 2초) → 단말: *"무 검은무늬병으로 보여요. 확률은 88%예요."*
4. 단말: *"뿌릴 수 있는 약은 ○○○ 수화제, 물 1,000배로 희석하세요. 수확 14일 전까지만 쓸 수 있어요. 다시 들으시려면 '다시'라고 말해주세요."*
5. 김 씨: "다시" → 농약 안내 반복
6. 결과는 단말 내부 이력에 저장. 인터넷 연결 없음

**성공 조건**: 화면을 한 번도 보지 않고 병명·농약명·희석배수를 들을 수 있음

### 시나리오 S4 — 음성 단말에서 재촬영 유도 (독립 단말, P1)

1. S3 진행 중 결과가 접전이면 단말: *"검은무늬병인지 노균병인지 헷갈려요. **잎을 뒤집어서 뒷면**을 카메라에 대주세요. 뒷면에 하얀 곰팡이가 있는지 볼게요."*
2. 김 씨가 잎을 뒤집어 대면 → 자동 촬영 → 재확정
3. 단말: *"뒷면을 보니 노균병이에요. …(농약 안내)"*

### 시나리오 S5 — 이력 조회·상담 (모바일 웹앱, P2·P3)

1. 지도사 이 씨가 농가 방문. 박 씨가 **이력** 탭을 연다
2. 카드 목록(썸네일·병명·날짜·신뢰도). 재촬영 건은 뱃지 표시
3. 카드를 누르면 상세: 사진(1차·2차), 결과, 당시 추천 농약
4. 같은 병이 2주 간격으로 반복 → 예방법 항목을 함께 확인

## 5. 예외·엣지 시나리오

| 상황 | 동작 |
|---|---|
| 잎이 아닌 사진(손, 바닥) | 신뢰도 낮음 안내 + "잎이 화면에 꽉 차게 다시 찍어주세요" |
| 지원하지 않는 작물 | 작물 선택 단계에서 3종만 노출. 향후 확장 안내 |
| 모델 미배포(개발 중) | Mock 모드로 전 구간 동작 (UI·흐름 검증 가능) |
| 단말 음성 인식 실패(바람·소음) | 2회 재시도 후 물리 버튼 안내: *"버튼을 눌러주세요"* |
| 단말 배터리 부족 | LED 빨강 점멸 + 음성 경고 |
| 농약 데이터 오래됨 | 관리자 스크립트로 PSIS 시드 갱신 (사용자 노출 없음) |

## 6. 사용자 여정 요약

```
[발견]  잎 이상 발견
   │
[촬영]  앱: 작물 선택 → 촬영          단말: 버튼/음성 → 자동 촬영
   │
[진단]  CNN 추론 (모바일: 서버 / 단말: NPU 오프라인)
   │
   ├─ 확신 ──────────────────────▶ [결과] 병명·신뢰도·심각도
   │
   └─ 혼동쌍 접전 ─▶ [유도촬영] 판별부위 안내 → 재촬영 → 융합 → [결과]
                                            │
[행동]  등록 농약·희석배수·PHI·예방법 ◀──────┘
   │
[기록]  이력 자동 저장 → 재발 추적·상담 근거
```

## 7. 스코프 (이번 학기)

**IN**
- A 모바일 웹앱: S1·S2·S5 전 구간 (이미 구현된 백엔드·프론트 위에 다듬기)
- B 단말: S3·S4를 **PC 프로토타입(웹캠+마이크+스피커)** 으로 먼저 검증 → 보드 도착 시 이식
- 모델 양자화(ONNX INT8) 및 NPU 변환 준비

**OUT**
- 사용자 로그인·농장별 이력 분리 (Phase 2)
- 작물 확장(토마토·오이 등)
- 병해충 중 "해충" 클래스
- 앱스토어 배포 (특허 출원 전 공개 금지)
