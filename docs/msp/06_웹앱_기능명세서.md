# 웹앱 페이지별 기능 명세서 — CropCare AI

> 과목: 모바일시스템응용프로젝트 · 팀명: 크래파스 · 작성일: 2026-09-08 · 상태: v0.1
> 대상: 웹앱 단계(보드 수령 전, ~7주차 중간 발표). 화면 ID는 [02_스토리보드](02_스토리보드.md) 기준.
> 담당 표기: FE=김민서(프론트엔드), CAM=고명준(카메라·음성), BE=박성호(백엔드), ML=김헌영(모델), INF=이서하(디바이스·인프라)

## 0. 공통

### 0-4. 공통 비기능 요구

- 모바일 퍼스트(480px 기준), 이미지 업로드 최대 10MB, 클라이언트에서 긴 변 1280px로 리사이즈 후 전송
- 진단 응답 목표 5초 이내 (서버 추론 2초 이내)
- 농약 정보는 DB(PSIS 시드) 값만 표시. 프론트에서 생성·가공 금지
- 오프라인·서버 오류 시 사용자에게 원인과 다음 행동을 한 문장으로 안내

## 1. M-01 홈 / 진단

**목적:** 작물을 고르고 한 번의 탭으로 촬영을 시작한다.

| ID | 기능 | 입력 | 동작 | 출력 / 상태 변화 | 담당 |
|---|---|---|---|---|---|
| M01-F1 | 작물 선택 | 칩 탭 (고추 / 배추 / 무) | 선택 칩 강조, 선택값 상태 저장 | crop_type 상태 갱신 | FE |
| M01-F2 | 촬영 시작 | 촬영 카드 탭 | 후면 카메라 호출 (getUserMedia, facingMode: environment) | 카메라 스트림 표시 → M-02 | CAM |
| M01-F3 | 갤러리 선택 | "사진 선택" 탭 | 파일 입력 (accept image/*) | 선택 파일 → M-02 | CAM |
| M01-F4 | 작물 미선택 방지 | 작물 미선택 상태에서 촬영 카드 탭 | 칩 흔들림 애니메이션 + 안내 문구 | 촬영 진행 안 됨 | FE |
| M01-F5 | 촬영 팁 표시 | 없음 | 정적 안내 2~3줄 | — | FE |
| M01-F6 | 음성 안내 | 화면 진입 | "작물을 고르고 잎을 찍어주세요" 낭독 (토글 켜진 경우) | — | CAM |

**예외**

- 카메라 권한 거부: "카메라 권한이 필요해요" 안내 + 갤러리 선택으로 대체 유도
- 카메라 미지원 브라우저: 촬영 카드를 파일 선택으로 자동 전환

## 2. M-02 촬영·업로드 미리보기

**목적:** 찍은 사진을 확인하고 진단을 요청한다.

| ID | 기능 | 입력 | 동작 | 출력 / 상태 변화 | 담당 |
|---|---|---|---|---|---|
| M02-F1 | 촬영 가이드 오버레이 | 카메라 스트림 | 잎 한 장이 차도록 프레임 가이드 표시, 밝기·흔들림 간이 체크 | 가이드 상태(양호/주의) | CAM |
| M02-F2 | 셔터 | 셔터 버튼 탭 | 캔버스 캡처 → JPEG 변환 | 미리보기 이미지 | CAM |
| M02-F3 | 미리보기 | 캡처 이미지 | 사진 + 선택 작물 표시 | — | CAM |
| M02-F4 | 다시 찍기 | 버튼 탭 | 미리보기 폐기, 카메라 재호출 | M-02 초기 상태 | CAM |
| M02-F5 | 진단하기 | 버튼 탭 | 이미지 리사이즈(긴 변 1280px) 후 POST /api/diagnose | M-03 표시 → 응답 시 M-04 또는 M-05 | CAM → FE |
| M02-F6 | 이미지 검증 | 파일 선택 시 | 형식(JPEG/PNG/WebP), 크기(10MB) 검사 | 실패 시 토스트 | CAM |

**예외**

- 업로드 실패(네트워크): "연결을 확인해 주세요" + 재시도 버튼, 이미지는 유지
- 서버 5xx: "잠시 후 다시 시도해 주세요"

| M04-F4 | 병해 정보 | description, causes, prevention | 증상·원인·예방 접이식 섹션 | — | FE |
| M04-F5 | 등록 농약 카드 | pesticides[] | 상표명, 희석배수, 사용법, PHI(수확 전 일수), 재출입 시간, 안전 문구 | — | FE |
| M04-F6 | 농약 없음 처리 | pesticides 비어 있음 | "등록 농약 정보가 없어요. 농업기술센터에 문의하세요" | — | FE |

| M04-F9 | 결과 낭독 | 응답 수신 | "고추 탄저병, 신뢰도 91%. 등록 농약 2종이 있어요" 낭독 | — | CAM |
| M04-F10 | 신뢰도 낮음 경고 | confidence < 0.5 이고 재촬영 유도 없음 | "확신이 낮아요. 다른 잎으로 다시 찍어보세요" 안내 | — | FE |

## 5. M-05 재촬영 유도 패널 ★

**목적:** 혼동쌍에 접전으로 떨어졌을 때 어느 부위를 왜 다시 찍어야 하는지 안내하고 2차 촬영을 받는다.

**발동 조건 (서버):** 상위 1·2위가 사전 정의 혼동쌍이고 신뢰도 마진이 임계값 미만이면 응답에 recapture 필드가 포함된다. 프론트는 이 필드 유무로만 판단한다.

| ID | 기능 | 입력 | 동작 | 출력 / 상태 변화 | 담당 |
|---|---|---|---|---|---|
| M05-F1 | 패널 표시 | recapture != null | 결과 위에 amber 톤 패널, 1차 결과는 흐리게 | — | FE |
| M05-F2 | 접전 표시 | top_predictions[0..1] | 두 후보 % 막대 그래프 | — | FE |
| M05-F3 | 판별부위 안내 | recapture.region, instruction | 부위명 굵게 + 촬영 지침 문장 | — | FE |
| M05-F4 | 후보별 단서 | recapture.candidates[] | 후보명 → 단서 문장 목록 | — | FE |
| M05-F5 | 2차 촬영 | "재확정" 버튼 탭 | 카메라 호출, 가이드 오버레이에 부위명 표시 | M-02 변형(재촬영 모드) | CAM |
| M05-F6 | 재확정 요청 | 2차 사진 확정 | POST /api/diagnose/{id}/refine | M-03 → M-06 | CAM → FE |
| M05-F7 | 건너뛰기 | "이대로 볼래요" 탭 | 패널 닫고 1차 결과를 정상 표시 | — | FE |
| M05-F8 | 음성 안내 | 패널 표시 | "두 병이 비슷해요. 잎 뒷면을 가까이 찍어주세요" 낭독 | — | CAM |

**예외**

- 재확정 API 실패: 1차 결과 유지, "재확정에 실패했어요" 안내, 재시도 가능
- 2차 촬영에서도 접전이면 서버는 융합 결과를 그대로 반환하고 유도는 반복하지 않음 (1회 한정)
