## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | CropCare AI — AI 기반 농작물 병해 진단 및 방제 지원 모바일·단말 서비스 |
| 한 줄 소개 | 사진 한 장(또는 말 한마디)으로 고추·무·배추 병해를 진단하고, 등록 농약·희석배수·안전사용기준까지 안내 |
| 대상 사용자 | 소규모 노지·시설 재배 농업인 (특히 고령층), 귀농인, 농업기술센터 지도사 |
| 산출물 | ① 모바일 웹앱 (Next.js + FastAPI + PyTorch) ② 오프라인 음성 진단 단말기 (Orange Pi 5) ③ 학습된 CNN 모델 및 양자화 모델 |
| 개발 기간 | 2026-09 ~ 2026-12 (약 14주) |

### 1-1. 배경 및 필요성

- 농작물 병해는 **조기 발견·조기 방제**가 피해 규모를 결정하지만, 농업인 다수가 병해를 정확히 구분하지 못한다
- 병명을 알아도 **등록 농약·희석배수·수확 전 사용금지 일수(PHI)** 를 찾는 과정이 번거로워 관행 살포로 이어진다
- 기존 이미지 진단 서비스는 사진 한 장의 확률만 제시한다. 그러나 실측 결과 **오분류의 59%가 특정 두 병해(무 검은무늬병 ↔ 무 노균병) 사이에서 발생**했고, 이는 모델 크기가 아니라 **입력 사진에 판별 정보가 없어서** 생기는 문제다
- 주 사용자인 고령 농업인은 작은 글씨·복잡한 앱·불안정한 통신 환경에서 스마트폰 앱을 쓰기 어렵다

### 1-2. 목표

1. **정확한 진단**: 9클래스 CNN 진단 test 정확도 90% 이상 유지 (현재 93.1%)
2. **혼동쌍 해결**: 접전 시 판별부위(잎 뒷면 등) 재촬영을 안내하고 다시점 융합으로 재확정 — 핵심 차별점
3. **행동으로 연결**: 진단 결과에 PSIS 등록 농약·희석배수·PHI·예방법을 자동 연결
4. **접근성**: 화면 없이 음성만으로 동작하는 오프라인 단말기 (Orange Pi 5 + NPU + 온디바이스 음성)

## 4. 시스템 구성

### 4-1. 아키텍처

```
┌──────────── 모바일 웹앱 ────────────┐      ┌──────────── 독립 단말 (Orange Pi 5) ────────────┐
│ Next.js (모바일 퍼스트)              │      │ device/agent.py                                │
│  홈·촬영·결과·재촬영패널·이력        │      │  버튼/음성 → 촬영(OpenCV) → HTTP(localhost)      │
└───────────────┬─────────────────────┘      │  결과 JSON → 음성 낭독 (SUDA / 폴백 TTS)          │
                │ HTTPS                        │  LED 상태 (GPIO)                                │
                ▼                              └───────────────┬────────────────────────────────┘
┌──────────────────────────── FastAPI 백엔드 (공통) ──────────────▼────────────────────────────┐
│ POST /diagnose  · POST /diagnose/{id}/refine  · GET /history  · GET /diseases                  │
│ 진단 서비스 ── 혼동쌍 판정(recapture) ── 융합 ── 농약 조회(PSIS seed) ── SQLite                  │
│ ML 런타임: torch (서버) | onnx (PC) | rknn (보드 NPU)                                            │
└────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 웹앱과 단말이 **같은 백엔드 코드**를 사용한다. 단말은 백엔드를 보드 안에서 localhost로 띄운다
- 단말의 음성 모델은 **창구** 역할만 하고, 농약명·희석배수·PHI 등 사실은 DB 값을 그대로 발화한다(환각 방지)

### 4-2. 기술 스택

| 영역 | 기술 |
|---|---|
| 프론트엔드 | Next.js 14, TypeScript, Tailwind CSS, Iconify(Lucide), Pretendard |
| 백엔드 | FastAPI, SQLAlchemy, SQLite, Pydantic |
| ML | PyTorch ResNet50 (9클래스), ONNX Runtime, RKNN Toolkit2 (NPU) |
| 데이터 | AI Hub 노지작물 질병 이미지, 농약안전정보시스템(PSIS) OpenAPI |
| 단말 | Orange Pi 5 16GB (RK3588S), USB AF 웹캠, USB 마이크, 스피커, GPIO 버튼·LED, 마음AI SUDA(온디바이스 음성, 지원 여부 확인 중) |
| 협업 | GitHub (khy1121/Cropy), Colab(GPU 학습), Docker Compose |

## 6. 역할 분담 (초안 — 팀 확정 후 수정)

오렌지파이 보드 수령 전까지는 **웹앱**으로 개발을 진행하고(중간 발표 시연물), 보드 수령 후 단말로 이식한다. 팀원 전원이 개발 파트를 맡고, 문서·발표는 로테이션으로 분담한다.

### 6-1. 개발 파트

| 역할 | 담당 | 웹앱 단계 (보드 수령 전, ~7주차) | 오렌지파이 단계 (보드 수령 후, ~14주차) |
|---|---|---|---|
| PM · 모델 | 김헌영 | 일정 관리, 병해충 데이터셋 정제·증강, CNN 분류 모델 학습·평가, ONNX export, 혼동쌍 분석 | 모델 경량화·양자화(RKNN) 변환, 단말 추론 정확도 검증, 재촬영 유도 판정 로직 |
| 프론트엔드 | (미정) | 웹앱 화면 구현(홈·촬영·결과·이력), 디자인 시스템 적용, 모바일 반응형·접근성 | 단말 화면 UI 이식(디스플레이 구성 시), 웹앱 유지보수 |

| 카메라 · 음성 | (미정) | 브라우저 카메라 모듈(getUserMedia, 촬영 가이드 오버레이, 이미지 전처리), Web Speech 기반 음성 안내(TTS/STT) | 카메라·마이크·스피커 조립 및 동작 검증, 단말 음성 통합(SUDA 또는 대체 엔진) |
| 디바이스 · 인프라 | (미정) | 부품 발주·PC 검수, RKNN 툴킷 환경 준비, Docker·CI 구성, 테스트 자동화 | 디바이스 에이전트, NPU 배포·속도 측정, OS 이미지·세팅 스크립트, 전력·발열 측정 |

### 6-2. 문서·발표 로테이션

- 주간보고는 팀장을 제외한 4명이 매주 순서대로 1명씩 작성하고, 팀장 검토 후 제출한다 (3주차부터 시작, 각자 3~4회).
- 중간·최종 발표 자료는 해당 주 담당자가 초안을 잡고, 각 파트 담당이 자기 파트를 채운다. 중간 발표와 최종 발표의 발표자는 다른 사람이 맡는다.
- QA는 파트별 자체 테스트를 원칙으로 하고, 통합 테스트는 13주차에 전원이 수행한다.

### 6-3. 코드 소유권 (폴더 단위)

코드 충돌을 막기 위해 폴더 단위로 소유자를 정하고, 폴더 간에는 API 계약으로만 연결한다.

| 역할 | 소유 폴더 | 다른 파트에 제공하는 것 |
|---|---|---|
| PM · 모델 | `ml/` | 모델 파일(ONNX/RKNN), 클래스 목록, 입력 전처리 규격 |
| 백엔드 | `backend/` | REST API 명세(OpenAPI 스키마) |
| 프론트엔드 | `frontend/src/app/`, `frontend/src/components/`, `frontend/src/types/` | — (최종 소비자) |
| 카메라 · 음성 | `frontend/src/features/camera/`, `frontend/src/features/voice/` (신설) | 프론트가 가져다 쓰는 React 컴포넌트·훅 |
| 디바이스 · 인프라 | `device/` (신설), `docker-compose.yml`, `.github/` | 실행 환경, CI |

**경계 규칙**

1. 자기 폴더는 자유롭게 커밋하고, 다른 파트 폴더는 PR로만 수정하며 해당 소유자의 리뷰를 받는다 (`.github/CODEOWNERS`로 강제).
2. 파트 간 접점은 계약 문서로 고정한다. 모델↔백엔드는 입출력 규격 문서, 백엔드↔프론트·디바이스는 OpenAPI 스키마, 카메라·음성↔프론트는 컴포넌트 props. 계약 변경 시에만 양쪽이 함께 논의한다.
3. `backend/app/services/ml_service.py`는 모델 로딩 코드로 소유는 백엔드, 모델 경로·전처리 규격은 PM·모델이 제공한다.
4. 폴더끼리 직접 import하지 않는다. 연결은 HTTP(백엔드↔프론트·디바이스)와 파일(모델→백엔드)로만 한다. 한 파트가 지연되어도 다른 파트는 목(mock) 응답으로 개발을 계속한다.

**단계별 공통 목표**

- 웹앱 단계: 스마트폰 브라우저에서 촬영 → 진단 → 결과·음성 안내까지 시연 (중간 발표)
- 오렌지파이 단계: 네트워크 없이 단말 단독으로 촬영 → 진단 → 음성 안내 시연 (최종 발표)

**비고**

1. 오렌지파이 보드 지급 전까지는 웹앱(스마트폰 브라우저) 기준으로 개발을 진행하며, 보드 지급 시점에 단말 이식 작업을 병행한다.
2. 위 역할 분담은 초안이며, 개발 진행 상황·기획 변경·팀원 역량 및 일정에 따라 팀 회의를 통해 조정될 수 있다.
3. 각 역할은 웹앱 단계의 산출물이 오렌지파이 단계로 이어지도록 구성하였으므로, 담당자는 두 단계를 연속으로 맡는 것을 원칙으로 한다.
4. 팀원별 세부 담당(고명준, 김민서, 박성호, 이서하)은 3주차 팀 회의에서 확정 후 본 문서와 `.github/CODEOWNERS`에 반영한다.
5. 보드 지급이 지연될 경우 최종 발표 시연 범위는 웹앱 + 단말 일부 기능(카메라·음성 안내)으로 축소할 수 있다.
6. 역할 변경 시 주간보고에 변경 사유와 변경 후 담당을 기록한다.

## 8. 기대 효과

- **농업인**: 병해 오판·관행 살포 감소, 등록 농약·PHI 준수로 안전한 농산물 생산
- **고령 사용자**: 화면 없이 음성만으로 진단 → 디지털 격차 완화
- **교육 효과**: 재촬영 안내를 통해 "어느 부위를 봐야 두 병이 구분되는지"를 사용자가 학습
- **기술적**: 온디바이스 NPU 추론 + 온디바이스 음성의 완전 오프라인 파이프라인 구현 사례
- **지식재산**: 혼동쌍 판별부위 유도촬영·다시점 융합 발명의 실시(reduction to practice)

## 9. 제약 및 유의사항

- **특허 출원 전 공개 금지**: 앱스토어 배포, 공개 시연, 논문 발표 금지. 수업 제출·발표는 비공개 범위로 한정하고 알고리즘 세부 수치는 발표 자료에서 제외

- 이미지 데이터(AI Hub)는 라이선스 범위 내 연구·교육 목적으로만 사용
- 사용자 사진은 이력 저장 목적 외 사용하지 않음 (Phase 2 인증 도입 시 개인정보 처리방침 작성)
