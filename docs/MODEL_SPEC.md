# CropCare AI - ML Model Specification

## 모델 개요

| 항목 | 값 |
|------|-----|
| 아키텍처 | **ResNet50** (ImageNet pretrained fine-tune) |
| Task | 9-class 이미지 분류 (병해 6 + 정상 3) |
| Input | 224×224 RGB, ImageNet mean/std 정규화 |
| Output | 9-class softmax |
| Framework | PyTorch 2.x / torchvision |
| 체크포인트 | `ml/checkpoints/best_model.pth` (약 94MB) |

보조 모델로 무 혼동쌍 전용 2-class 분류기(`ml/checkpoints/pair_mu.pth`, ResNet18)가 있다.
[혼동쌍 유도촬영](#혼동쌍-유도촬영) 참고.

## 학습 데이터

**AI Hub「노지 작물 질병 진단」**(073) 원천데이터. 파일명에 인코딩된 작물·병해 코드를
`ml/prepare_dataset.py`가 파싱해 ImageFolder 구조로 분할한다.

```
V006_79_{type}_{disease:02d}_{crop:02d}_{area:02d}_{grow:02d}_{risk}_...
```

병해는 `disease` 코드로, 정상(`type=0`)은 `crop` 코드로 분류한다.
클래스 균형을 위해 정상 클래스는 클래스당 200장(`--normal-cap`)으로 제한한다.

|--------|------:|----:|-----:|
| 0 고추탄저병 | 350 | 75 | 75 |
| 1 고추흰가루병 | 350 | 75 | 75 |
| 2 무검은무늬병 | 350 | 75 | 75 |
| **3 무노균병** | **175** | **38** | **38** |

| 6 고추정상 | 350 | 75 | 75 |

| 8 배추정상 | 350 | 75 | 75 |

무노균병(3)은 원천 데이터 자체가 적어 다른 클래스의 절반이다. 이 불균형이
아래 성능 분석의 배경이 된다. `train.py --balanced-sampler`로 역빈도 가중
샘플링을 걸 수 있다.

**Augmentation (train):** RandomResizedCrop(scale 0.7~1.0), HorizontalFlip,
Rotation(±15°), ColorJitter(brightness/contrast 0.3, saturation 0.2)
**Loss/Optim:** CrossEntropy(label_smoothing=0.1), AdamW(wd=1e-4), CosineAnnealingLR

## 추론 파이프라인

1. 이미지 로드 (PIL, RGB 변환)
2. Resize → ToTensor → Normalize (ImageNet mean/std)
3. Model forward → softmax
4. `(model_class_id, confidence)` 전체 분포를 내림차순 정렬
5. 응답에는 상위 3개, 다시점 융합에는 전체 분포를 사용
6. `model_class_id` → DB `diseases` 조인

추론 해상도는 체크포인트의 `img_size` 필드를 따르며, 필드가 없는 구버전
체크포인트는 224로 폴백한다. **현재 배포된 `best_model.pth`에는 이 필드가 없다**
(아래 [알려진 이슈](#알려진-이슈) 참고).

### 오류 분포 — 유도촬영의 근거

test 637장 중 오분류는 44건이고, 그중 **26건(59.1%)이 무 검은무늬병(2)과
무 노균병(3)의 상호 오분류**다.

```
실제 2 → 예측 3 : 19건
실제 3 → 예측 2 :  7건
```

두 병은 초기 병징이 육안으로도 유사하고, 잎 앞면만 찍은 사진으로는 구분 정보가
충분치 않다. **모델 용량이나 학습량의 문제가 아니라 입력에 판별 정보가 없는 문제**이며,
여기서 유도촬영 설계가 나온다.

배추 혼동쌍(4↔5)은 3건으로 훨씬 적지만 같은 성격의 오류라 함께 정의해 두었다.

## 혼동쌍 유도촬영

`backend/app/services/recapture.py` 구현.

### 1) 혼동 판정

1차 진단의 상위 두 후보가 사전 정의된 혼동쌍이고, 신뢰도 마진(1위 − 2위)이
**0.20 미만**이면 재촬영을 유도한다.

| 혼동쌍 | 판별부위 | 판별 단서 |
|--------|----------|-----------|
| 2 무검은무늬병 ↔ 3 무노균병 | 잎 뒷면 | 뒷면 회백색 포자층 → 노균병 / 뒷면 깨끗 + 앞면 동심원 병반 → 검은무늬병 |
| 4 배추검은썩음병 ↔ 5 배추노균병 | 잎맥·잎 가장자리 | 잎맥 흑변 + V자 황변 → 검은썩음병 / 뒷면 회백색 포자 + 각진 반점 → 노균병 |

> 병리 단서는 표준 병징에 근거하나, 배포 전 식물병리 자료로 검증이 필요하다.

### 2) 다시점 융합

2차 사진을 받으면 1차·2차의 **전체 분포**를 가중 평균한다.
2차는 판별부위를 표적 촬영한 것이므로 가중을 크게 준다.

```
fused[c] = 0.4 · dist1[c] + 0.6 · dist2[c]
```

### 3) 혼동쌍 전용 분류기

`pair_mu.pth`(ResNet18, 2-class)가 있으면 그 쌍이 차지한 **합계 질량은 보존한 채
내부 비중만** 전문가 확률로 재분배한다. 쌍 밖 클래스는 영향받지 않는다.

```
combined = fused[a] + fused[b]
fused[a] = combined · spec[a] / (spec[a] + spec[b])
```

적용 조건: 전문가 분류기가 학습한 두 클래스가 **1차 진단의 상위 두 후보와 일치**할 때만.
이 게이트가 없으면 무 전용 분류기가 배추 혼동쌍 재촬영에도 적용되어 무 후보의
순위가 근거 없이 뒤집힌다.

## 알려진 이슈

**1. 혼동쌍 전용 분류기가 아직 이득을 주지 못한다**

`pair_mu.pth`의 자체 test 성능은 **76.1%**(113장; 검은무늬병 84.0% / 노균병 60.5%)다.
같은 쌍에 대한 9-class 본 모델의 쌍 내부 판별력은 78/104 = **75.0%**로 사실상 차이가 없다
(단, 두 수치는 서로 다른 분할에서 나온 값이라 직접 비교는 아니다).

원인으로 의심되는 지점: `prepare_pair.py`는 AI Hub 원천에서 **병해 코드로만** 이미지를
모은다. 즉 전용 분류기의 학습 데이터도 본 모델과 같은 일반 촬영 사진이며,
정작 판정 대상인 **잎 뒷면 근접 사진으로 학습된 적이 없다.** 학습·서빙 도메인이
어긋나 있어, 판별부위 이미지가 포함된 데이터 확보가 선행되어야 한다.

**2. 체크포인트에 `img_size` 메타데이터가 없다**

현재 `best_model.pth`는 `img_size` 필드 없이 저장돼 추론·평가가 모두 224로 폴백한다.
해상도별 val 정확도를 실측한 결과 **224px 94.7% / 256px 94.5% / 288px 95.3%**로,
224 폴백이 유의미한 손실을 내고 있지는 않다 (288의 +0.6%p는 4장 차이).
다만 학습 해상도를 체크포인트만으로 재현할 수 없다는 문제는 남으므로,
재학습 시 `train.py`가 기록하는 `img_size`를 유지해야 한다.

**3. 무노균병 데이터 부족**

학습 175장으로 다른 클래스의 절반이다. `--balanced-sampler`와 추가 데이터 확보가
2·3 혼동 완화의 가장 직접적인 수단이다.

## 재현 명령

```bash
# 데이터 준비
python prepare_dataset.py --src "<AI Hub 원천데이터 경로>" --out ../data/dataset

# 학습
python train.py --data-dir ../data/dataset --arch resnet50 --epochs 20 --balanced-sampler

# 평가 (분할별)
python evaluate.py --data-dir ../data/dataset --split test [--tta]

# 혼동쌍 전용 분류기
python prepare_pair.py --out ../data/mu_pair
python train.py --data-dir ../data/mu_pair --arch resnet18 --output checkpoints/pair_mu.pth
```
